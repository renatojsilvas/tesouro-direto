## `src/`

### R1 — Repos re-registram os DapperTypeHandlers como "defesa em profundidade"
- `src/TesouroDireto.Infrastructure/Persistence/Repositories/PrecoTaxaReadRepository.cs:11-14`
- `src/TesouroDireto.Infrastructure/Persistence/Repositories/TituloReadRepository.cs:12-15`
> `AddInfrastructure` já chama `DapperTypeHandlers.Register()` no boot (MatchNamesWithUnderscores +
> handler de `DateOnly`), mas o construtor de cada read-repo **repete** o registro como
> defesa em profundidade para testes que instanciam o repositório **direto, fora do container de DI**.
> Sem isso, um teste unitário que crie o repo na mão pega o mapeamento Dapper default e quebra.

### R2 — Cenários não sinalizam "projeção utilizada"
- `src/TesouroDireto.Application/Simulador/SimularCenariosCommandHandler.cs:97-98`
> Diferente do simulador simples, os cenários **não consultam** o serviço de projeção:
> o `ProjecaoAnual` vem sempre do request, por cenário. Logo não há "projeção utilizada"
> a devolver/sinalizar na resposta de cenários (ausência proposital, não esquecimento).

### R3 — Taxas de cupom semestral são constantes de domínio hardcoded
- `src/TesouroDireto.Domain/Simulador/SimuladorService.cs:141` e `:145`
> Conversão anual→semestral dos cupons: **Prefixado com cupom (NTN-F) = 10% a.a.** e
> **IPCA+/IGP-M+ com cupom (NTN-B) = 6% a.a.**, ambos convertidos por `(1 + taxa)^0.5 − 1`.
> São os valores canônicos dos títulos com cupom do Tesouro; ficam embutidos no cálculo.

### R4 — Componente Blazor pode estar disposed após desconexão do circuit
- `src/TesouroDireto.Web/Components/Pages/Historico.razor:201`
> O bloco é guardado porque, após a desconexão do circuit (Blazor Server), o componente
> pode já ter sido **disposed** quando o callback assíncrono retorna — daí o tratamento
> defensivo em vez de assumir que o componente ainda está vivo.

## `tests/`

### R5 — Override de URL de import usa UM ESPAÇO, nunca `""`
- `tests/TesouroDireto.API.Tests/Integration/ApiTestFactory.cs:117-122`
> `Environment.SetEnvironmentVariable(nome, "")` **remove** a variável (não a seta vazia).
> Para forçar o branch "URL não configurada" nos serviços de import **sem** I/O externo,
> seta-se um **único espaço**: passa por `IsNullOrWhiteSpace` (tratado como não-configurado)
> e ainda existe como variável. String vazia falharia os dois objetivos.

### R6 — Limpeza manual de env vars quando `InitializeAsync` falha no meio
- `tests/TesouroDireto.API.Tests/Integration/ApiTestFactory.cs:106-109`
> xUnit só chama `DisposeAsync` se `InitializeAsync` **completar com sucesso**. Se
> `StartAsync`/`MigrateAsync` falhar no meio, as env vars setadas precisam ser limpas
> **manualmente ali** antes de deixar a exceção propagar — senão vazam para o resto do
> processo de teste.

### R7 — `MemoryCache` não expõe `TimeProvider`; adapter para o `ISystemClock` legado
- `tests/TesouroDireto.API.Tests/Projecoes/CachedProjecaoMercadoServiceTests.cs:33-36`
> `Microsoft.Extensions.Caching.Memory` (mesmo na 9.x) **não** expõe `TimeProvider` em
> `MemoryCacheOptions` — só o `ISystemClock` legado (`Clock`). Um adapter fininho faz o
> `MemoryCache` seguir o **mesmo relógio fake** do decorator, permitindo testar TTL/expiração
> sem `sleep` real. (Complementa a decisão já registrada em `tarefa26-28` de injetar o
> relógio fake direto no decorator, não via slot genérico de `TimeProvider`.)

### R8 — Contrato real: POST /importacao com URL não configurada → 200, não 400
- `tests/TesouroDireto.API.Tests/Integration/ImportacaoEndpointsTests.cs:44-69`
> **Divergência deliberada da matriz de testes** (que esperava 400): o
> `ImportCsvCommandHandler` trata cada item de falha do stream **apenas incrementando
> `LinhasComErro`** e seguindo o loop — nunca propaga como `Result` de erro. Então o
> endpoint devolve **200 OK** com `ImportResult(..., LinhasComErro: 1)`. O mesmo vale para
> `/importacao/feriados` (sem URL, só loga e encerra o stream; zero efeito colateral,
> nunca chama `AddRangeAsync`/`SaveChanges`).

### R9 — Bug real coberto: streams HTTP não são seekable e o ExcelDataReader exige seek
- `tests/TesouroDireto.API.Tests/Feriados/FeriadoImportServiceTests.cs:51-52`
> Cenário exato que causou o bug: streams HTTP **não são seekable**, mas o `ExcelDataReader`
> **exige seek** — daí a necessidade de bufferizar o conteúdo antes de ler a planilha de feriados.
